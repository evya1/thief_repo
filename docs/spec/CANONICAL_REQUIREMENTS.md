## Interpretation rules

1. IDs are permanent and must not be renumbered.
2. `PROJECT SPECIFICATION` items define game/submission behavior; `QUALITY MODEL` items retain their stated review level and are not silently promoted into game-validity rules.
3. Examples and sample code are not requirements unless an explicit source statement makes them binding.
4. Appendix F controls numeric values. Fixed, Minimum, and Negotiated statuses are preserved.
5. Any unresolved ambiguity is referenced by an `OPEN-xxx` item; downstream implementation must not guess.
6. Architecture choices not in this register are `DERIVED DESIGN DECISION`s and belong in PLAN or ADR, not here.
