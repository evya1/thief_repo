## Relevant context

`PLANQ-002` is resolved and recorded in `docs/spec/OPEN_QUESTIONS.md`. This task executes that baseline; it does not reopen the selection.

| Item | Recorded value |
|---|---|
| CI/runtime baseline | Python 3.12, read from `config/repo_quality.toml` |
| Declared runtime range | `requires-python = ">=3.12"`, narrowed only if real dependency compatibility forces it |
| FastMCP | direct runtime dependency, `fastmcp>=3.4,<4` |
| Test/quality tooling | `pytest`, `pytest-cov`, `ruff`, `pre-commit`, `pyyaml` — preserved as they are |

| Out of scope | GUI toolkit (`PLANQ-007`), Gmail sender (`PLANQ-005`), optional model provider (`PLANQ-003`) |

The `<4` upper bound keeps the runtime on the current stable major line while its successor is still prereleased. Re-verify the bound at execution time rather than assuming it; if the bound no longer resolves, report it instead of widening it silently.

### Current state (verified 2026-08-16)

A `uv.lock` exists on the integration branch, but it does **not** satisfy the recorded baseline: `pyproject.toml` declares `dependencies = []` and the lock contains no `fastmcp` entry. The lock therefore covers the test/quality tooling only. `implementation_state` is `partial`: the remaining work is adding the FastMCP runtime dependency, regenerating the lock, and adding the import smoke test.

This task selects the *initial* foundation dependency baseline only. Do not install a package here merely because a later component might need it.

`pyproject.toml` and `uv.lock` are repository-global, whole-environment integration artifacts with serialized mutation ownership. T002 owns their initial creation. A later component task does not automatically inherit that ownership: if a human-approved implementation decision later requires a dependency change, the component worker surfaces the requirement to the orchestrator, who explicitly assigns serialized dependency-integration work before either file is edited. A component worker must not silently widen its own write set to reach these files.

The Python baseline that CI installs is read from `config/repo_quality.toml`, which this task reads but does not own; changing that value is outside this write set and needs an orchestrator-approved write-set change.

This task owns `.github/workflows/ci.yml`, whose uv bootstrap was repaired ahead of it under `docs/decisions/ADR-002-ci-uv-bootstrap.md`: CI installs a pinned, checksum-verified uv release instead of a third-party marketplace action. Inherit that decision rather than reopening it. When the approved lock lands, change `uv sync --all-groups` to `uv sync --locked --all-groups` and leave the bootstrap step unchanged.
